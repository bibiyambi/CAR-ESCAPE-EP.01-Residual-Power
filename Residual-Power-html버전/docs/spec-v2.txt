설정 이름과 의미
설정 항목 이름은 “화면 조작 보조”다. 내부 키는 screenControlAssist다. OFF에서는 지원되는 차량 기능의 조작 버튼·레버·슬라이더를 게임 화면에서 숨긴다. 사용자가 차량의 물리 조작부 또는 차량 기본 설정에서 바꾼 상태를 앱이 읽어 단서를 갱신한다. ON에서는 게임 전용 패널로 동일한 상태를 가상 생성하며 실차에 명령을 보내지 않는다.

실제 조작 범위의 정의
“차량에서 직접 조작할 수 있는 부분”은 이 빌드의 검증된 차량 입력 목록에 등록된 기능을 뜻한다. 현실에 부품이 존재한다는 이유만으로 연동 기능으로 간주하지 않는다. 등록되지 않은 기능은 처음부터 게임 전용 오브젝트로 명시한다. 시트·미러·선루프·벨트는 본 설계에서 게임 전용이다. 모든 차량 조작 없이 완주하려면 ON을 선택한다.
전환과 오류
ON으로 시작한 뒤 OFF를 선택하면 해당 막의 필수 신호·권한·연결·정차 판정을 점검한다. 하나라도 불충족이면 OFF 전환을 완료하지 않고 사유와 ON 유지 또는 재점검을 제시한다. OFF 중 연결을 잃으면 현재 단계가 대기 상태가 되며 ON 전환을 사용자가 선택할 수 있다. 자동 성공 처리나 숨겨진 가상 조작 패널은 제공하지 않는다.
모드 전환은 이미 획득한 단서와 아이템을 보존하고 미완료 입력 시퀀스만 초기화한다. 새 모드에서 기준 상태를 새로 읽고 새 조작부터 판정한다. 이전 모드의 이벤트를 합쳐 퍼즐을 완료하지 않는다. 본편 저장은 유지하며 ON으로 전환해도 실패나 감점은 없다.

읽기 전용 어댑터
앱은 차량 설정을 변경하지 않는다. OFF에서 사용자가 직접 변경한 상태를 구독해 게임에 반영한다. 차량 신호 API가 존재해도 대상 차량에서 읽을 수 있다는 보장은 없으므로, 기능 점검 결과와 실제 수신 로그를 검증 기준으로 삼는다. V00·V01·V02는 기획용 내부 이름이며 실제 SDK 메서드 이름이 아니다.
정차와 사용자 편의
정차·주차 판정을 충족할 때만 두 모드의 게임을 활성화한다. 기준 제안은 속도 0과 검증된 주차 상태이며 기어 P 또는 주차브레이크의 사용 조합은 플랫폼별 확인 후 고정한다. 관련 신호가 없으면 실차용 빌드는 실행을 차단한다. 개발용 모의 실행은 별도 빌드로 구분한다.
주행 징후·판정 불명·연결 끊김 발생 시 게임 입력과 음향을 중지하고 상태를 저장한다. 다시 허용돼도 사용자의 재개 입력을 기다린다. 벨트 분리, 실제 시트 이동, 미러 시야 변경, 선루프 개방은 요구하지 않는다. 공조는 풍량만 선택적으로 사용하며 온도·A/C·내기순환 강제 변경은 제외한다. OFF 사용자는 공조 불편 시 설정에서 ON으로 바꿔 같은 단계부터 계속한다.
3 전체 스토리와 정보 공개
1막 잔류 전원
기억이 흐릿한 주인공은 M-04 운전석에서 깨어난다. 양옆은 운송 프레임에 막혀 있다. 비에 가린 카메라와 빈 좌석의 가방, 차량 인계 기록을 조사한다. 자신의 목소리와 필체가 남긴 단서를 따라 가상의 선루프를 열고 탈출한다. 끝에는 01~04 프레임과 비어 있는 05, 다른 차의 경고음이 보인다.
2막 누락된 다섯 번째 기록
화면 속 주인공은 시설 감시실로 이동한다. 현실 플레이어는 계속 주차된 차량 안에 있다. 감시실에는 M-04가 회수한 진단 기록을 읽는 단말이 있다. 정비용 수신기에서 차량 상태를 바꾸면 해당 진단 계층의 흔적이 드러난다는 규칙을 발견한다. 과거 동료 윤서는 범인이 아니라 이송 명단을 외부로 보내려던 협력자였고, M-05를 이용해 탈출을 시도했다. 주인공은 구조 요청을 전송하고 M-04의 스마트키와 프레임 해제용 토큰을 얻는다.
3막 마지막 시동
M-04로 돌아오지만 프레임은 이중 잠금 상태다. 윤서의 기록과 두 사람의 음성을 대조해 탈출 준비 중 남긴 순서를 복원한다. 차량 신호를 이용한 진단 응답으로 프레임과 출구의 게임 속 인터록을 차례로 풀고 스마트키를 삽입한다. 마지막 시동과 이동은 게임 화면 연출이다. 시설을 빠져나가면 이미 송신된 명단의 수신 확인과 “이번에는 기억해”라는 윤서의 메시지가 도착한다.
사건의 진실
주인공은 차량 소프트웨어 개발자로서 실종된 동료 윤서의 흔적을 추적하다 시설에 잠입했다. 붙잡힌 뒤 한 차례 깨어났을 때 미래의 자신을 위한 도구와 녹음을 숨겼다. 윤서는 감시를 피해 채널을 나눠 말했고, 주인공은 자기 기록을 진단 계층에 분산했다. 시설은 차량 회수 기록으로 사람의 이동을 위장했다. 약물에 의한 기억 공백이 반복 탈출처럼 보이지만 초자연적 반복은 아니다.

3막의 진행 구조와 제작 범위
전체 목표 플레이 시간은 45~60분의 제안값이다. 1막 15~20분, 2막 15~20분, 3막 10~15분과 전환 연출로 구성한다. 시간 제한이나 실패 시 사망은 기본으로 사용하지 않는다. 추리는 자유롭게 하되 물리적 아이템의 선행 조건만 적용한다.

막 사이의 차량 입력
2막·3막의 차량 조작은 현실 사용자가 시설로 이동해야 한다는 뜻이 아니다. 게임 단말이 M-04의 진단 데이터를 받고, 현실 차량 조작이 그 진단 입력에 대응하는 인터랙션 규약이다. 이 규칙은 2막 첫 단말의 장치 설명과 신호 반응으로 보여준다. 시설 배경에 실제 차량 패널을 복제해 배치하지 않는다.
발견과 입력의 분리
단서 열람은 해법을 알려주는 정보이며 조작 자체를 잠그는 조건은 아니다. 도구나 연결 토큰 등 물리적 선행 조건이 없는 한 올바른 행동을 먼저 수행해도 수용한다. 진단 시퀀스는 해당 단말이 활성화된 후 새로 수신된 이벤트만 판정한다. 평소 차량을 사용하면서 과거에 발생한 조작은 수집하지 않는다.
P01~P15의 수치·회전 방향·문서 표·대사는 제작 기준 제안이다. 이하 “유지”의 시간 기준은 공통 0.7초 안정 수신이며 연속 입력 제한 시간은 없다. 값이 안정되지 않으면 대기하고 순서 오류는 현재 퍼즐 단계만 초기화한다. 완성한 기록과 아이템은 사라지지 않는다.

5 게임 화면과 차량 입력 패널
S01~S14는 모두 앱 안의 화면이다. 현실 공간은 사용자가 주차한 차량이고 화면 속 장소는 M-04 및 폐쇄 시설이다. 게임 배경의 문·좌석·유리는 이야기와 탐색에 사용하며 그 부품에 실제로 접근할 필요가 없다. S04A는 게임 오디오, S04B는 게임 룸미러 확대 패널이다.
화면 | 장소와 이동 | 입력 및 게임 조작
S00 | 시작과 설정 → S01 또는 저장 화면 | 화면 조작 보조와 연결 점검
S01~S03 | 운전석 ↔ 조수석 ↔ 뒷좌석 | P01~P03와 P05. 와이퍼·풍량은 모드별 입력
S04A와 S04B | 원래 화면 위 확대 후 복귀 | 게임 오디오와 게임 룸미러
S05~S06 | 시트 아래 → 천장 → 1막 엔딩 | 화면 오브젝트 조작
S07~S08 | 감시실 전경 ↔ 진단 단말 | P08 와이퍼와 P09 풍량
S09~S10 | 음성 보관실 ↔ 송신실 | 녹음 조합·명단 정렬·회수함

레이아웃
상단에는 막·연결 상태와 일시정지를 둔다. 중앙은 장소와 단서, 하단은 아이템·수첩·화면 이동이다. ON의 차량 입력 패널은 별도 오버레이다. OFF에서는 오버레이 진입 버튼까지 제거한다. 게임 전용 오디오나 미러에는 “게임 장치”라는 구분을 최초 조사 시 표시한다. 설명은 입력 출처를 알려주며 정답 순서는 알려주지 않는다.

6 이벤트 처리와 저장
단일 판정 흐름
OFF의 VehicleReadAdapter와 ON의 SimulationAdapter가 같은 정규화 이벤트를 생성한다. PuzzleEngine은 sourceMode와 sessionEpoch가 현재 설정과 일치하고 V00가 허용 상태인 이벤트만 받는다. OFF 입력은 읽기 전용이며 ON에서 수신한 실차 변화는 게임 판정에서 무시한다.
필드 | 의미
signalKey와 normalizedValue | V01 OFF 또는 ACTIVE, V02 LOW 또는 MID. 실제 허용값 매핑은 프로필에 저장
sourceMode와 sessionEpoch | VEHICLE 또는 SIMULATION, 전환 때 증가하는 세션 번호
timestamp와 quality | 수신 시각과 유효성. 제안상 마지막 유효 수신 2초 초과 시 대기
puzzleId와 stepIndex | 현재 단말의 미완료 시퀀스. 무관한 신호는 무시
capabilityProfileId | 대상 차종·SDK·권한 및 검증된 입력 매핑 식별자
신호 정규화
풍량 LOW와 MID는 센서 원시값을 고정 숫자로 가정하지 않는다. 지원 범위를 사전 확인해 서로 구별되는 쾌적한 두 단계로 매핑한다. 두 단계가 없으면 OFF를 제공하지 않는다. 와이퍼 ACTIVE는 검증한 저속 또는 간헐 모드 중 한 값이다. AUTO는 임의로 ACTIVE로 간주하지 않는다. 같은 값의 중복 알림은 시퀀스의 다음 단계로 세지 않는다.
저장과 전환
schemaVersion=2, mode, chapter, currentScreen, inventory, clues, completedPuzzles, storyFlags를 저장한다. 미완료 차량 시퀀스와 정차 허용 상태는 복원하지 않고 새 수신으로 재검증한다. 시간 대기와 오디오 위치는 일시정지할 수 있지만 이전 신호는 재사용하지 않는다. 저장 이전 버전의 1막 완료는 유지하고 가방 끈·가상 미러 등 변경된 상태는 변환표로 초기화한다. 변환 실패 시 원본 저장을 보존하고 새 게임 선택을 제공한다.
7 구현 작업과 수용 기준
기능 ID | 구현 완료의 의미
F01 모드 설정 | ON과 OFF의 패널 표시 및 입력 출처를 일치
F02 사전 점검 | V00~V02 읽기 지원과 권한, 현재 연결 상태로 OFF 허용
F03 정규화 | 검증한 원시값을 V 신호로 변환하고 중복·오래된 값 제거
F04 퍼즐 엔진 | P01~P15의 조작과 화면 추리를 분리해 판정
F05 탐색과 아이템 | 게임 오브젝트 조사·조합·문서 확대·수첩
F06 저장과 복구 | 모드 전환 및 중단 후 영속 진행 복원
F07 연출 | 3막 전환, 녹음·자막, 게임 시동·엔딩
F08 검증 기록 | 차종별 입력 프로필과 ON/OFF 완주 기록 보관
검수 ID | 통과 조건
AC01 | OFF 화면에서 V01·V02 조작 패널과 진입 버튼 없음
AC02 | OFF에서 물리 조작 후 유효 신호 수신으로만 단서 변화
AC03 | ON에서 실차 조작 없이 3막 완주, 차량 쓰기 호출 0건
AC04 | 미지원·권한 거부·단절 때 자동 성공 또는 자동 모드 전환 없음
AC05 | 모드 전환 전후 이벤트를 합쳐 시퀀스를 완료하지 않음
AC06 | 각 막에서 와이퍼 또는 풍량 입력과 추리로 해결하는 필수 퍼즐 존재
AC07 | 벨트 해제·시트 이동·미러·선루프·실제 시동 요청 없음
AC08 | V00 불허 또는 오래된 신호에서 두 모드 모두 정지
AC09 | P02와 P03의 순서 교환 및 단서 선행 없이 정답 조작 가능
AC10 | P15에서 명단·프레임·출구·키 조건을 각각 누락해 진행 차단 확인
AC11 | 풍량 범위 부족·와이퍼 AUTO·중복 알림으로 오판정 없음
AC12 | 글자·음향·자막만으로 각 퍼즐을 접근 가능하게 검토
8 제작 자산과 연동 확인 기록
제작 자산
1막은 차량 내부 6개 시점과 확대, 2막은 감시실·진단실·음성 보관실·송신실, 3막은 복귀 차량·프레임 단말·출구 지도·게임 계기판을 제작한다. 공통 아이템은 사진·카드·리더기·도면·삼각 도구·진단 스트립·스마트키·토큰이다. 환경 자산은 비와 와이퍼, 게임 결로, 경고음, 프레임 잠금음이다. 모든 장면은 어두운 현실적 미스터리 톤과 동일한 차량 식별번호 M-04를 유지한다.
차량 프로필 확인표
확인 항목 | 현재 상태와 기록할 증거
플랫폼과 SDK 버전 | 미확정. 대상 장치와 버전 기록
V00 정차 판정 | 미검증. 속도·주차 판정 신호와 실패 시 동작 로그
V01 와이퍼 | 도메인 확인. 원시값·권한·실제 콜백 수신 미검증
V02 풍량 | 도메인 확인. 두 풍량 구간과 변경 수신 미검증
오디오·글로브박스 개폐·룸미러 | 실차 연동 미채택. 지원 확인 전 범위 확대 금지
실차 OFF 배포 | V00~V02 전부 검증 전에는 활성화하지 않음
공식 문서 확인 범위
2026년 11월 11일 열람한 Pleos Vehicle SDK 소개는 차량 기능의 상태 조회와 기능 지원 확인, 비동기 결과 및 변경 구독 구조를 설명한다. Wiper와 HVAC 도메인이 안내돼 있어 입력 후보로 채택했다. 이는 특정 차종에서 본 설계의 입력을 사용할 수 있다는 검증 결과가 아니다.
